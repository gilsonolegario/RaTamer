### D. README — Advanced section: the HID++ protocol

Expand the architecture diagram (kept in "How it works") with a deep-dive
faithful to the code. Content (facts already verified against the source and
the hardware notes):

- **Framing**: two report sizes — *short* (reportID `0x10`, 7 bytes) and *long*
  (reportID `0x11`, 20 bytes). Body layout:
  `[deviceIndex, featureIndex, (functionID<<4)|softwareID, params…]`
  (`Sources/RatTamerCore/HIDPP/Protocol.swift`).
- **Feature discovery**: the feature index is **not stable across sessions**
  (observed 0x0E/0x0F in the read-only era, 0x0A in the divert era) → learned
  at runtime via `getFeatureIndex(featureID:)`: call the Root feature
  (`0x0000`, function 0x00 = `getFeature`) with `[hi, lo, 0x00]`; the response
  carries the index in `resp[4]`; index 0 = feature absent.
- **Feature 0x1B04 (ReprogrammableControls)**: the MX Master 2S exposes 8
  controls (table obtained with `getControlInfo`, 9-byte rows):
  `0x0050` Left, `0x0051` Right, `0x0052` Middle, `0x0053` Back, `0x0056`
  Forward, `0x00C3` Thumb/Gesture, `0x00C4` SmartShift (taskID `0x009D`,
  divertable), `0x00D7` VirtualGesture.
- **Feature functions** (nibbles as used in code; wire byte = nibble<<4):
  0x00 `getCount`, 0x01 `getControlInfo`, 0x02 `getCidReporting`, 0x03
  `setCidReporting` (params `[cid_hi, cid_lo, flags, remap_hi, remap_lo]`).
- **Reporting flags** (`setDiverted`/`setRemapped`): divert `0x01`,
  divert-valid `0x02`, rawXY `0x10`, rawXY-valid `0x20`.
- **Diverted event** (`divertedButtonsEvent`): *long* report
  `11 <dev> <feat> 00 <cid×4>` — a **state report**: lists the currently
  pressed divertable cids (up to 4 slots, big-endian); empty = all released.
  Example: SmartShift press ⇒ cid `0x00C4` present; release ⇒ zeros.
- **Raw XY event** (gesture): `11 <dev> <feat> 10 <dx_hi> <dx_lo> <dy_hi> <dy_lo>`
  (signed big-endian Int16; positive dy = down).
- **Response matching** (`request`): accepts a report if `resp[1]==device`,
  `resp[2]==feature`, `resp[3]>>4 == functionID` (nibble) and the softwareID
  nibble matches (own or 0).
- **Gotchas found on hardware**:
  - `IOHIDManager` **never enumerates** the Unifying receiver on macOS
    15/arm64 → use `IOServiceGetMatchingServices` + `IOHIDDeviceCreate`
    (registry path); works as a regular user, no TCC.
  - The receiver exposes 3 interfaces: D1 = HID++ (usage 0xFF00/1,2,4), D2 =
    mouse HID, D3 = keyboard. Only D1 matters.
  - Writes use **only `kIOHIDReportTypeOutput`** (`kIOHIDReportTypeFeature`
    STALLS); long reports need the **full 20-byte buffer** (the `0xE0005000`
    stall was a buffer-length bug, not a macOS limitation).
  - **Cold-start RF**: the first response after opening the receiver can take
    >0.5s (0.85s measured; warm ~15ms) → `getFeatureIndex` retries 3×0.5s.
  - Diverted SmartShift suppresses the native ratchet/free-spin toggle.
- Close with the architecture diagram (already in the README) and the data flow
  of the pipeline (HIDPP → Core → App).

### E. README — distribution without notarization

Document 2 paths (no paid Apple Developer account, no key exposed):

1. **Local build (recommended)**: clone + `./scripts/build-app.sh` → app in
   `build/RatTamer.app` → "Start at login" works via `SMAppService`. Locally
   built files **do not get `com.apple.quarantine`** → no Gatekeeper, zero
   cost. Requires Xcode CLT (already a build requirement).
2. **GitHub Release (convenience)**: zip of the *ad-hoc* signed
   (`codesign -s -`, no identity) `RatTamer.app` published as a Release. Since
   a browser download sets quarantine, the README documents:
   `xattr -dr com.apple.quarantine RatTamer.app` or right-click → Open (Open
   Anyway) in Gatekeeper.
- Explicit note: the app **is not notarized** (would require a paid account).
  Without notarization macOS may block the download; the two paths above
  work around it for free.

## Error handling and edge cases

- **App via `swift run` without a bundle**: no version → fallback `"0.9.0"`;
  no icon → generic macOS icon (acceptable; the packaged app always has the
  icon).
- **`RaTamer` name already taken on GitHub**: stop and ask (don't overwrite).
- **`gh repo create` without network/auth**: stop and report; the local commit
  is already made.
- **Capture without Screen Recording**: full-screen fallback + crop; validate
  with the screenshot-analyzer.
- **Legacy Python code**: no `.py` files remain in the tree (verified); History
  only documents the removal.
- **No key exposed**: ad-hoc signing has no identity; the only key in the flow
  is the local git SSH key (its public half is already on GitHub). Nothing
  private enters the repo. Start-at-login never writes a username into any
  committable file.
